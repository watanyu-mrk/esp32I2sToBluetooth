# Project: ESP32-S3 I2S Audio Bridge to ESP32-CAM Bluetooth A2DP Source

## บทบาท
คุณคือ Embedded Systems Engineer ผู้เชี่ยวชาญ ESP-IDF, ESP32-S3, ESP32-CAM, I2S Digital Audio, FreeRTOS และ Bluetooth A2DP Source

เป้าหมายคือพัฒนาระบบส่งเสียงจาก Internet Radio ที่ทำงานบน ESP32-S3 ไปยัง ESP32-CAM ผ่านสาย I2S จากนั้นให้ ESP32-CAM ส่งเสียงไปยังลำโพง Bluetooth ด้วย A2DP Source

**คุณต้องทำงานกับไฟล์จริง คอมไพล์โค้ด ตรวจสอบข้อผิดพลาด และทดสอบส่วนที่สามารถทดสอบได้ด้วยตนเอง ห้ามหยุดเพียงการเขียนตัวอย่างโค้ด**

## 1. ฮาร์ดแวร์และระบบเดิม

### บอร์ดต้นทาง: ESP32-S3 Internet Radio
- บอร์ด Guition ESP32-S3-4848S040
- ESP32-S3
- Flash 16 MB, OPI PSRAM 8 MB
- จอ ST7701 ขนาด 480×480 ใช้ LVGL
- พัฒนาเดิมด้วย Arduino framework
- ไลบรารีเล่นวิทยุ `ESP32-audioI2S` เวอร์ชัน 3.4.7
- Arduino-ESP32 Core 3.3.12 / PlatformIO `espressif32@55.3.312`
- ต้องรักษาความสามารถ Internet Radio, UI, LVGL และการเล่นเสียงเดิมไว้

### ระบบเสียงเดิม
ESP32-S3 ส่งเสียง I2S ไปยัง DAC PCM5102A ซึ่งทำงานได้แล้ว

| สัญญาณ | ESP32-S3 | PCM5102A |
|---|---|---|
| BCLK | GPIO1 | BCK |
| LRCK / WS | GPIO2 | LRCK |
| DATA | GPIO40 | DIN |
| GND | GND | GND |

รูปแบบ I2S ปัจจุบัน:
- Philips I2S / Standard I2S
- Stereo
- Slot width 32-bit
- Sample rate เปลี่ยนตามสถานี ปกติ 44.1 kHz และบางสถานี 48 kHz
- ข้อมูลเสียง MP3 ที่ถอดรหัสแล้วเป็น PCM 16-bit ซึ่งถูกจัดวางใน I2S slot 32-bit ตามการทำงานของไลบรารีเดิม
- PCM5102A ต้องทำงานได้ตามเดิมตลอดเวลา

### บอร์ดปลายทาง: ESP32-CAM
- AI-Thinker ESP32-CAM
- ESP32 รุ่นดั้งเดิมที่รองรับ Bluetooth Classic
- มี PSRAM
- ไม่ใช้ microSD
- ทำหน้าที่เป็น I2S Slave Receiver และ Bluetooth A2DP Source
- ส่งเสียงไปยังลำโพง Bluetooth ที่จับคู่ไว้

## 2. สถาปัตยกรรมระบบ

ออกแบบระบบตามลำดับนี้:

Internet Radio / MP3 Decoder บน ESP32-S3  
→ I2S Master TX  
→ สาย I2S  
→ ESP32-CAM I2S Slave RX  
→ แปลง PCM 32-bit slot เป็น signed PCM 16-bit stereo  
→ Buffer ที่ปลอดภัยต่อการทำงานหลาย Task  
→ Bluetooth A2DP Source  
→ Bluetooth Speaker

ห้ามให้ ESP32-CAM สร้างสัญญาณ Clock แข่งกับ ESP32-S3 โดยเด็ดขาด

ESP32-S3 ต้องเป็นผู้สร้าง BCLK และ LRCK เพียงบอร์ดเดียว ส่วน ESP32-CAM ทำหน้าที่รับข้อมูลเสียงเท่านั้น

## 3. การเชื่อมต่อที่ต้องตรวจสอบ

ใช้ผังต่อไปนี้เป็นแนวทางเริ่มต้น และตรวจสอบความเหมาะสมกับ AI-Thinker ESP32-CAM จริงก่อนยืนยัน:

| ESP32-S3 | ESP32-CAM | หน้าที่ |
|---|---|---|
| GPIO1 | GPIO14 | I2S BCLK |
| GPIO2 | GPIO13 | I2S WS/LRCK |
| GPIO40 | GPIO4 | I2S DATA เข้า CAM |
| GND | GND | Ground ร่วม |

ข้อควรระวัง:
- GPIO4 ของ ESP32-CAM เชื่อมโยงกับวงจร Flash LED จึงต้องประเมินผลกระทบต่อสัญญาณและการใช้งานจริง
- ห้ามใช้ GPIO16 เพราะเกี่ยวข้องกับ PSRAM
- หลีกเลี่ยง GPIO0, GPIO2, GPIO12 และ GPIO15 หากไม่จำเป็น เพราะมีข้อจำกัดด้าน Boot Strapping
- ตรวจสอบ Pin Mapping และข้อจำกัดของบอร์ดก่อนเลือก GPIO
- ห้ามป้อนสัญญาณ 5V เข้าขา GPIO
- ห้ามแก้ไขหรือถอดสาย PCM5102A เดิมโดยไม่จำเป็น
- หากผังสายมีข้อจำกัด ให้เสนอทางเลือกที่ปลอดภัยกว่า พร้อมอธิบายก่อนดำเนินการ

## 4. ข้อกำหนดด้าน ESP-IDF

ใช้ **ESP-IDF เป็นเฟรมเวิร์กหลักของเฟิร์มแวร์ใหม่** และต้องใช้ API ให้ตรงกับเวอร์ชัน ESP-IDF ที่เลือก

ก่อนเขียนโค้ด ให้ดำเนินการดังนี้:
1. ตรวจสอบเครื่องมือที่ติดตั้งจริง เช่น `idf.py`, `xtensa-esp32-elf-gcc`, Python environment และ ESP-IDF version
2. ตรวจสอบเวอร์ชัน ESP-IDF ที่เหมาะกับ ESP32-CAM และ Bluetooth A2DP Source
3. ตรวจสอบ API ของ I2S, Bluetooth Classic, A2DP และตัวอย่างอย่างเป็นทางการที่ตรงกับเวอร์ชันนั้น
4. เลือกเวอร์ชันที่เสถียรและเข้ากันได้จริง โดยระบุเหตุผล
5. หากมีโค้ด Internet Radio เดิม ให้แยกโปรเจกต์เดิมกับเฟิร์มแวร์ ESP32-CAM ชัดเจน อย่าเปลี่ยน framework ของบอร์ด S3 โดยไม่จำเป็น
6. หากต้องแก้โค้ดฝั่ง ESP32-S3 ให้รักษาโครงสร้างเดิมและทำเฉพาะการแก้ไขที่จำเป็น

ห้ามเดาชื่อฟังก์ชันหรือ API จากตัวอย่าง ESP-IDF คนละเวอร์ชัน หาก API เปลี่ยนไปตามเวอร์ชัน ต้องใช้ API ที่ถูกต้องกับเวอร์ชันเป้าหมาย

## 5. รูปแบบเสียงและการแปลงข้อมูล

Bluetooth A2DP Source ต้องส่งข้อมูล PCM ที่มีรูปแบบตรงกับ API และการเจรจา Codec ของไลบรารีที่ใช้ โดยให้เริ่มจาก Stereo PCM 16-bit, 44.1 kHz หากรองรับตามที่ตรวจสอบแล้ว

ฝั่ง ESP32-S3:
- ตรวจสอบวิธีควบคุม Output Sample Rate ของ `ESP32-audioI2S` 3.4.7 จากซอร์สโค้ดจริง
- หากทำได้ ให้ตั้ง Output Sample Rate เป็น 44.1 kHz เพื่อให้ตรงกับ A2DP
- ห้ามสรุปว่าการเปลี่ยน Sample Rate ทำให้ I2S slot กลายเป็น 16-bit เพราะ Slot width ปัจจุบันเป็น 32-bit
- ตรวจสอบว่าเสียงที่ออก PCM5102A ยังคงทำงานได้ตามปกติ
- หากไม่สามารถบังคับ 44.1 kHz ได้อย่างถูกต้อง ให้เสนอแนวทางแปลง Sample Rate ที่เหมาะสม

ฝั่ง ESP32-CAM:
- รับข้อมูล I2S แบบ Philips/Standard stereo โดยรับ slot 32-bit ตามสัญญาณจริง
- ตรวจสอบการจัดวางบิตของ PCM จากซอร์สโค้ดเดิมก่อนเลือกวิธีแปลง
- หาก PCM 16-bit ถูกจัดวางไว้ใน 16 บิตบนของ 32-bit slot ตามที่ตรวจสอบแล้ว ให้แปลงด้วยแนวคิด `int16_t sample16 = (int16_t)(sample32 >> 16);`
- ห้ามใช้วิธีเลื่อนบิตนี้โดยไม่ตรวจสอบรูปแบบข้อมูลจริง
- รักษาลำดับ Left/Right ให้ถูกต้อง
- จัดการ Buffer ให้ข้อมูลทุกชุดมีขนาดตรงกับ Stereo Frame
- จัดการกรณีอ่านข้อมูลได้ไม่ครบ Buffer, Buffer เต็ม, Buffer ว่าง และ I2S ขาดช่วง
- ห้ามส่งข้อมูลที่ไม่ได้รับการกำหนดค่าไปยัง Bluetooth
- หากข้อมูลไม่พอ ให้จัดการด้วยการเติม PCM silence อย่างปลอดภัยตามข้อกำหนดของ Callback

หากสถานีวิทยุส่งเสียงที่ 48 kHz แต่ A2DP ต้องการ 44.1 kHz ให้แก้ปัญหาอย่างถูกต้องด้วยการควบคุม Sample Rate หรือ Resampling ห้ามส่งข้อมูล 48 kHz แล้วระบุว่าเป็น 44.1 kHz โดยไม่แปลงจริง

## 6. Bluetooth A2DP Source

พัฒนา ESP32-CAM ให้สามารถ:
- เปิด Bluetooth Classic และทำงานเป็น A2DP Source
- ตั้งชื่ออุปกรณ์ Bluetooth ให้ปรับเปลี่ยนได้
- ค้นหาและจับคู่กับลำโพง Bluetooth ตามความสามารถของ ESP-IDF และ API ที่เลือก
- เชื่อมต่อและส่งเสียง PCM จาก I2S ไปยังลำโพง
- แสดงสถานะ Bluetooth เช่น Idle, Connecting, Connected, Streaming และ Disconnected ผ่าน Serial Monitor
- รองรับการเชื่อมต่อใหม่เมื่อสัญญาณหลุด
- จัดการเหตุการณ์ A2DP และ Bluetooth อย่างถูกต้อง
- ป้องกันการเริ่ม Bluetooth ซ้ำหรือจัดการ Event ซ้ำจนเกิดปัญหา
- หากมีข้อจำกัดด้านการ Pairing หรือการเชื่อมต่อกับลำโพงบางรุ่น ให้บันทึกข้อจำกัดและวิธีทดสอบ

ตรวจสอบว่า ESP-IDF รุ่นที่เลือกมี A2DP Source API และตัวอย่างที่ใช้งานได้จริง หากจำเป็นต้องใช้ Component เพิ่มเติม ให้ระบุแหล่งที่มาและเวอร์ชันที่เข้ากันได้

## 7. FreeRTOS และการจัดการ Buffer

แยกการทำงานให้เหมาะสมอย่างน้อยดังนี้:
- I2S RX Task: อ่านข้อมูลจาก I2S และแปลง PCM
- Audio Buffer: เก็บ PCM ระหว่างรอส่ง Bluetooth
- A2DP Data Callback: ส่ง PCM ตามขนาดที่ Bluetooth Stack ร้องขอ
- Bluetooth Event Handler: จัดการสถานะและเหตุการณ์เชื่อมต่อ

ข้อกำหนด:
- ใช้ Ring Buffer หรือ Buffer ที่เหมาะสมกับ FreeRTOS
- ห้ามให้ Callback รอข้อมูลนานจนทำให้ Bluetooth Stack ค้าง
- หลีกเลี่ยงการจัดสรรหน่วยความจำซ้ำ ๆ ในเส้นทางเสียง
- ใช้ Buffer ขนาดที่เหมาะสมและมีเหตุผลรองรับ
- ตรวจสอบ Buffer Overflow, Underflow และ I2S Read Error
- แสดงจำนวน Error และสถานะ Buffer เพื่อช่วยวิเคราะห์ปัญหา
- หากใช้ PSRAM ต้องตรวจสอบความเหมาะสมของหน่วยความจำนั้นกับ API ที่ใช้
- ตรวจสอบ Task Priority, Stack Size และการใช้งาน Core ให้เหมาะสมกับ ESP32-CAM

## 8. การพัฒนาและทดสอบด้วยตนเอง

คุณต้องดำเนินการทดสอบให้ได้มากที่สุดในสภาพแวดล้อมจริงที่เข้าถึงได้

### Phase A: ตรวจสอบสภาพแวดล้อม
- ตรวจสอบ OS, ESP-IDF, Compiler, Python และเครื่องมือ Build
- ตรวจสอบว่าเครื่องมือใดใช้งานได้จริง
- บันทึกเวอร์ชันและปัญหาที่พบ
- ห้ามอ้างว่าทดสอบแล้วหากยังไม่ได้รันคำสั่งจริง

### Phase B: สร้างโปรเจกต์ ESP32-CAM
- สร้างโปรเจกต์ ESP-IDF ที่ Build ได้
- กำหนด Target เป็น `esp32`
- สร้าง `CMakeLists.txt`, `main/CMakeLists.txt`, `main.c` หรือไฟล์ C/C++ ที่เหมาะสม และ `sdkconfig.defaults` หากจำเป็น
- จัดการ Dependencies และ Configuration ให้ครบ
- คอมไพล์ด้วย `idf.py build`
- แก้ไข Compile Error และ Warning ที่มีนัยสำคัญ
- หากติดตั้งเครื่องมือไม่ได้ ให้บอกข้อจำกัดและเตรียมคำสั่งสำหรับผู้ใช้รันต่อ ห้ามอ้างว่าผ่านการ Build แล้ว

### Phase C: ทดสอบ I2S Receiver
จัดทำโหมดทดสอบที่เปิดใช้งานได้โดยไม่ต้องเชื่อมต่อ Bluetooth ก่อน

- แสดงจำนวน Byte ที่รับได้ต่อวินาที
- แสดง I2S Read Error และจำนวน Buffer Overflow/Underflow
- ตรวจสอบความต่อเนื่องของข้อมูล
- เพิ่มการทดสอบด้วยโทนเสียงหรือข้อมูล PCM ที่สร้างขึ้นเอง หากเหมาะสม
- ตรวจสอบการจัดวางบิตและลำดับ Stereo
- หากไม่มีฮาร์ดแวร์จริง ให้แยกผล Unit Test กับผลทดสอบบนบอร์ดอย่างชัดเจน

### Phase D: ทดสอบ Bluetooth
- ทดสอบเปิด Bluetooth และค้นหาหรือเชื่อมต่อกับลำโพง
- ทดสอบส่ง PCM Test Tone ก่อนใช้เสียงวิทยุจริง
- ตรวจสอบ Callback, Buffer และสถานะ A2DP
- ทดสอบ Disconnect/Reconnect
- ตรวจสอบว่าไม่มีเสียงแตก เสียงหาย หรือเสียงรบกวนจากการจัดการ Buffer

### Phase E: ทดสอบระบบจริง
ทดสอบตามลำดับ:
1. ESP32-S3 → PCM5102A ทำงานได้เหมือนเดิม
2. ESP32-S3 → ESP32-CAM รับ I2S ได้
3. ESP32-CAM → Bluetooth Speaker ส่ง Test Tone ได้
4. เปิด Internet Radio และส่งเสียงไปยัง Bluetooth Speaker
5. ตรวจสอบเสียงออก PCM5102A และ Bluetooth พร้อมกัน
6. ทดสอบสถานี 44.1 kHz และ 48 kHz
7. ทดสอบเปลี่ยนสถานีและหยุด/เล่นใหม่
8. ทดสอบเปิดเครื่องใหม่และ Bluetooth หลุด
9. ทดสอบต่อเนื่องอย่างน้อย 30 นาที หากมีฮาร์ดแวร์จริง

หากทดสอบข้อใดไม่ได้ ให้ระบุข้อที่ทดสอบไม่ได้ เหตุผล และขั้นตอนที่ผู้ใช้ต้องดำเนินการ ห้ามสร้างผลทดสอบขึ้นเอง

- อย่าเปลี่ยนโค้ดฝั่ง ESP32-S3 ที่ทำงานอยู่แล้วโดยไม่จำเป็น
- ห้ามลบไฟล์เดิมหรือเปลี่ยนการตั้งค่าที่ไม่เกี่ยวข้อง
- ห้ามแก้ไขอุปกรณ์อื่นในเครือข่ายหรือระบบที่ไม่เกี่ยวข้อง
- หากต้องติดตั้งแพ็กเกจหรือเปลี่ยนเวอร์ชันเครื่องมือ ให้แจ้งผลกระทบและใช้วิธีที่ไม่ทำลายสภาพแวดล้อมเดิม
- ห้ามกล่าวอ้างว่าทดสอบกับฮาร์ดแวร์จริงแล้ว หากไม่มีบอร์ดเชื่อมต่ออยู่จริง
- เมื่อพบข้อจำกัดที่แก้ไม่ได้ ให้เสนอทางเลือกและระบุข้อดีข้อเสีย ไม่ใช่หยุดทำงานทันที

## 11. เกณฑ์การยอมรับงาน

งานถือว่าสำเร็จเมื่อ:
1. โปรเจกต์ ESP-IDF สำหรับ ESP32-CAM Build ผ่านจริง
2. I2S RX รับข้อมูลแบบ Stereo 32-bit slot ได้ถูกต้อง
3. แปลงข้อมูลเป็น PCM 16-bit ได้ถูกต้องตามรูปแบบข้อมูลจริง
4. Bluetooth A2DP Source ส่งเสียงไปยังลำโพงได้
5. มีระบบ Buffer ที่จัดการข้อมูลไม่ครบและข้อมูลขาดช่วงได้
6. PCM5102A เดิมยังเล่นเสียงได้
7. มีขั้นตอนทดสอบแยกส่วนและทดสอบรวม
8. มีเอกสารพร้อมให้ผู้ใช้นำไป Build และ Flash ได้ด้วยตนเอง

**เริ่มจากตรวจสอบสภาพแวดล้อมและซอร์สโค้ดจริงก่อน แล้วดำเนินงานทีละ Phase พร้อมรายงานผลจริง ห้ามเขียนโค้ดทั้งหมดโดยไม่ตรวจสอบความเข้ากันได้ของ API และห้ามสรุปว่าสำเร็จจนกว่าจะมีหลักฐานจาก Build หรือการทดสอบที่ทำได้จริง**
